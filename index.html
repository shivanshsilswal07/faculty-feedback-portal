What the portal does

Everything needed to collect and read academic feedback

Built around the four things a feedback system actually needs: a simple form, a way to stay anonymous, protection against duplicate answers, and a dashboard that turns numbers into a picture.

Structured rating forms

Students rate teaching effectiveness, clarity, punctuality and more using stars, sliders and scales — not a single vague "how was it?" box.

Anonymous or identified

Every submission lets the student choose whether their name is attached to their answers, explained clearly at the point of choice.

Duplicate-submission checks

Once feedback is submitted for a course and faculty pairing, the form recognizes it and stops a second submission for the same pairing.

Visual admin dashboard

Administrators see average ratings, bar-style comparisons, and course-wise or faculty-wise breakdowns at a glance.

Process

How feedback moves through the portal

  1. Log in — the student signs in with their Student ID (demo login, explained on the About page).
  2. Select a course — the course list is mapped to the faculty who actually teach it, using the Course & Faculty Mapping table.
  3. Rate and write feedback — the student rates several aspects of the course and can add written comments.
  4. Confirm and submit — a confirmation checkbox is required before the form can be sent.
  5. Review results — administrators read summarized averages and charts on the Admin Dashboard.

Before you submit

Feedback guidelines

Be specific
Mention what actually helped or didn't — "more solved examples in class" is more useful than "make it better".
Be respectful
Feedback is read by real people. Describe the teaching, not the person.
One submission per pairing
Each course-and-faculty combination accepts one feedback submission per student, per semester.
Anonymous means anonymous
If you choose anonymous mode, your name and ID are never shown with your ratings.

FAQ

Frequently asked questions

Can I edit my feedback after submitting?

Not in this version. This keeps evaluation data consistent for the semester it was submitted in.

Is my anonymous feedback really untraceable?

Anonymous feedback is hidden from every page that displays results: your name is never shown and your registration number is never shown. In this demo, the record still keeps your name and registration number inside your own browser so the duplicate check works. A real system would remove them before storing.

Who can see the Admin Dashboard?

In a real deployment, only authorized staff. In this CA1 demo, the Admin page is open for evaluation purposes and clearly marked as sample data.

Does this project use a real database?

It uses a local database: submitted feedback is saved in the browser's localStorage and shown under Recent Feedback. It stays inside one browser on one device, because this is a static project built for GitHub Pages. A real system would store it on a server.
